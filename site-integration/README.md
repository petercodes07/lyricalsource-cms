These files are the matching changes for the existing LyricalSource Next.js website, deployed separately from the Express CMS. They are tracked here so the shared API contract, database migration, cache dependencies, and public pagination can be reviewed together. Do not run this directory as a standalone website.

Copy the relevant files into the website checkout, preserving their paths. Back up the live CMS SQLite database with `scripts/backup.js`. Run the website's `scripts/migrate-cms-scale.mjs` from its checkout with a new private backup directory and an ownership mapping exported from the CMS `article_owners` table. Use a database migration account, not the restricted application account. The script loads `.env.local`, respects externally supplied DB_USER/DB_PASSWORD, streams private content backups before altering tables, adds columns/indexes only when missing, and preserves staff ownership. Do not commit the backup or ownership export.

Build the website into a separate Next distDir, retain the old working build for rollback, and switch the website before restarting the new CMS. Forms opened before deployment must be reopened: saves without a matching version return 409, preserving entered content. A website rollback can leave the additive database columns/indexes in place. Roll back both application layers together if necessary.

Every CMS write checks edit_version under a row lock and increments it in the same transaction. Do not add other content writers that bypass this check. New articles also receive cms_owner_id; existing author access needs the ownership backfill. MySQL content remains authoritative; SQLite holds staff access, sessions, and short-lived editor presence. Keep a single CMS process for this server. Additional hosts will require moving staff/session/presence storage to a shared database.
